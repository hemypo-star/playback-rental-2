# 05 — План работ

Репозиторий `hemypo/playback-rental`, **ветка `2.0`**, дерево `50bf48a4`.
Цель работ — **`apps/cms`**. `main`/`prod` не трогаем, корневой `src/` не трогаем.

## Что изменилось против прошлой редакции этого файла

Прошлая редакция целилась в корневой `src/` (Vite + React 18 + shadcn + Supabase,
Tailwind v3). Это легаси-приложение: оно живёт в `main`/`prod` и выводится из
эксплуатации. Настоящий сайт 2.0 — одно Next-приложение `apps/cms`:

| | Легаси (`src/`) | Живое (`apps/cms`) |
|---|---|---|
| Фреймворк | Vite + React 18 + react-router | Next 16 App Router + React 19 |
| Данные | Supabase через REST | Payload 3, Local API в том же процессе |
| Мутации | `fetch` из компонентов | Server Actions |
| Стили | Tailwind v3 + `tailwind.config.ts` | Tailwind v4, токены в `@theme` |
| Состояние | React Context | `nanostores` |
| Админка | `src/pages/admin/*` | `(admin)/admin/*` + штатная Payload на `/cms` |

Маршруты живого приложения: `(frontend)` — витрина, `(admin)` — админка оператора,
`(payload)` — `/cms` и `/api/*`.

**Из пакета удалены `tailwind.config.ts` и `index.css`.** Это была замена конфигов
легаси-приложения на Tailwind v3. В `apps/cms` Tailwind v4, токены объявлены в
`@theme` внутри `src/styles/global.css`, и они **уже соответствуют дизайну** —
цвета, радиусы, тени, шрифт Golos Text (self-hosted, не Google Fonts). Применять
старые файлы нельзя: они сломают сборку и откатят токены.

## Как теперь доставляется дизайн

Через существующий конвейер, а не через markdown-инструкции:

```bash
node tools/design-sync.mjs extract "Playback Rental - прокат техники.html"
node tools/design-sync.mjs spec
node tools/design-sync.mjs audit apps/cms/src
```

`spec` кладёт в `docs/design-reference/spec/` два файла, которые импортируются из
`global.css`: `tokens.css` (кривые и длительности как утилиты Tailwind) и
`interactions.css` (24 правила состояний). Оба помечены «не править руками».
Правки дизайна идут в исходный бандл, оттуда `extract` + `spec`.

Роль этого пакета после смены цели — **справочная спека, а не инструкция по внедрению**:

| Файл | Статус |
|---|---|
| `01-tokens.md` | справка по значениям; живой источник — `@theme` в `global.css` |
| `02-primitives.md` | 14 примитивов; перепривязать к компонентам `apps/cms/src/components/*` |
| `03-motion.md` | язык движения; машинная часть — `spec/tokens.css` + `design-sync audit` |
| `04-screens.md` | экран за экраном; привязка к файлам требует обновления на `(frontend)` |
| `06-audit.md` | аудит легаси-приложения, архив |
| `07-audit-apps-cms.md` | аудит живого приложения — рабочий документ |

## Порядок работ

### Ш1 — Перепроверить аудит против живого кода

`06-audit.md` снят с легаси. Часть находок в `apps/cms` не существует по построению
(валидация через перехват кликов, четыре точки входа в админку, фильтры в
`location.state`), часть перенеслась вместе с кодом. Результат — `07-audit-apps-cms.md`.

**Приёмка:** каждая находка старого аудита имеет статус: перенеслась / снята новым
стеком / изменилась; новые находки описаны по файлам `apps/cms`.

### Ш2 — Свести цену в одно место

Сейчас логика суток продублирована:

- `apps/cms/src/lib/pricing.ts` — «display-only», комментарий ссылается на удалённый `apps/web`
- `apps/cms/src/lib/rental/pricing.ts` — серверная правда, вызывается хуком `beforeValidate`

Обе копии считают одинаково и одинаково ошибаются: `Math.ceil(hours / 24)`, а при
совпадающих датах `hours = 0` → `return 0`, то есть 0 ₽ вместо одних полных суток.
Это открытые пункты 1 и 3 старого аудита, они пережили переезд.

**Сделать:** оставить `lib/rental/pricing.ts` единственным источником, `lib/pricing.ts`
свести к реэкспорту или удалить, вычистить комментарии про `apps/web`. Решить и
записать в JSDoc конвенцию суток (12→14 авг = 3 суток по календарным суткам владения),
привести к ней `calculateRentalDays` и `lib/dateRange.ts`. Минимум — 1 сутки.

**Приёмка:** одинаковые даты дают одни полные сутки и полную ставку; витрина и хук
`beforeValidate` дают одно и то же число; юнит-тест `price(base, d) === base * d` для d = 1…30.

### Ш3 — Движение

Прогнать `design-sync audit apps/cms/src` и закрыть расхождения: 86 переходов на
дефолтной кривой Tailwind вместо `ease-expo`, `duration-200` вместо `duration-240`,
неиспользуемые `bnPop` / `bnRise` / `bnBar`, отсутствующие `group-hover` на зумах
обложки героя и фото товара.

**Приёмка:** audit без ⚠ по витрине; `prefers-reduced-motion` соблюдается.

### Ш4 — Экраны

По `04-screens.md`, источник истины по разметке — `docs/design-reference/template.html`.
Порядок: каталог и карточка товара → корзина и чекаут → главная → правовые и контакты.
Админка `(admin)` — после витрины; пять её экранов дизайн не описывает вовсе
(Категории, Акции, Медиатека, Пользователи, Настройки), ориентир — соседние экраны.

**Приёмка:** постранично, глазами против `template.html`, плюс `design-sync audit` без новых ⚠.

## Что не делать

- Не открывать PR в `main`/`prod`, не бэкпортить.
- Не трогать корневой `src/` — он выводится из эксплуатации.
- Не применять `tailwind.config.ts` и `index.css` из прошлых редакций этого пакета.
- Не править `spec/tokens.css` и `spec/interactions.css` руками — затрёт следующий прогон.
- Не заводить новые тени, радиусы, кривые, цвета. Система закрыта.
- Не переносить дизайн в штатную админку Payload (`/cms`) — у неё своя тема.
- Не полагаться на дефолтное кэширование Next там, где читается наличие: устаревший
  сток в каталоге — известный класс багов этого переезда.
