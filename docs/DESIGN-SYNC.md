# Выгрузка дизайна из Claude Design

Короткий ответ на «как выгрузить бандл, чтобы упростить интеграцию»: **выгружать
ничего заново не нужно** — файл `Playback Rental - прокат техники.html` в корне
репозитория уже содержит полную спецификацию всех пяти экранов, включая каждый
ховер, переход и анимацию. Проблема была не в формате выгрузки, а в том, что
перенос делался глазами. `tools/design-sync.mjs` делает его механическим.

## Что внутри бандла

Это не HTML-страница, а самораспаковывающийся артефакт. Четыре блока
`<script type="__bundler/*">`:

| Блок | Что там |
|---|---|
| `manifest` | base64 (+gzip для JS) — рантайм артефакта и 4 woff2 Golos Text |
| `template` | JSON-строка с реальной разметкой **всех экранов**, `{{ }}`-биндинги |
| `page_order` | порядок страниц |
| `ext_resources` | внешние ссылки |

Логика экранов (состояние, демо-данные, вычисления) лежит не в манифесте, а
вложенным `<script type="text/x-dc">` внутри самого шаблона.

**Почему бандл «не работает», если открыть его в браузере.** Вся стилизация —
inline `style="..."`, а состояния заданы двумя нестандартными атрибутами:

```html
<div style="transition:transform 420ms cubic-bezier(0.16,1,0.3,1)"
     style-hover="transform:translateY(-4px);box-shadow:0 26px 48px -32px rgba(10,10,10,0.42)">
```

`style-hover` и `style-focus` применяет рантайм артефакта. Ни один браузер их не
понимает, и ни один сборщик про них не знает — поэтому при ручном переносе они
теряются первыми. Команда `spec` превращает их в настоящий CSS.

## Как пользоваться

```bash
# 1. Распаковать бандл (после каждого нового экспорта из Claude Design)
node tools/design-sync.mjs extract "Playback Rental - прокат техники.html"

# 2. Собрать спеку: токены движения + все hover/focus как реальный CSS
node tools/design-sync.mjs spec

# 3. Сверить код со спекой
node tools/design-sync.mjs audit apps/web/src
```

Зависимостей нет, Node 22+ хватает.

`extract` проверен на текущем бандле: `template.html` и `dc_script.js`
воспроизводятся байт в байт с тем, что уже лежит в `docs/design-reference/`.

## Что даёт `spec`

`docs/design-reference/spec/tokens.css` — токены движения для Tailwind v4:

```css
@theme {
  --ease-expo: cubic-bezier(0.16,1,0.3,1);       /* 63× в дизайне */
  --ease-overshoot: cubic-bezier(0.34,1.56,0.64,1); /* 8× */
  --ease-inout: cubic-bezier(0.45,0,0.15,1);     /* 2× */
  --duration-240: 240ms;  /* 99× — доминанта */
  --duration-420: 420ms;  /* 21× */
  ...
}
```

После импорта этого файла `ease-expo`, `duration-240` и т.д. становятся обычными
утилитами Tailwind. Кривая перестаёт быть числом, которое можно забыть скопировать.

`interactions.css` — 24 различных правила состояний, каждое с исходным
`transition` и комментарием, где в дизайне оно встречается:

```css
/* 4× · div · «{{ s.value }}» */
.d-hz7o3v {
  transition:transform 420ms cubic-bezier(0.16,1,0.3,1),box-shadow 420ms cubic-bezier(0.16,1,0.3,1);
}
.d-hz7o3v:hover {
  transform:translateY(-4px);
  box-shadow:0 26px 48px -32px rgba(10,10,10,0.42);
}
```

Имена классов детерминированы (хэш от значения), так что повторный прогон после
правок в Claude Design даёт осмысленный diff, а не переименование всего разом.

`spec.json` — то же машиночитаемо, если понадобится кодогенерация.

```

  ⚠ cubic-bezier(0.34,1.56,0.64,1)   дизайн   8×   код  2×
  ⚠ cubic-bezier(0.45,0,0.15,1)      дизайн   2×   код  0×

ДЛИТЕЛЬНОСТИ
  доминанта дизайна:           240ms (99×)
  ⚠ duration-200          75×  — в дизайне такой длительности нет

СОСТОЯНИЯ
  hover-правил в дизайне:      60
  hover:-классов в коде:       176
  group-hover: в коде:         0

АНИМАЦИИ ПОЯВЛЕНИЯ
  ⚠ bnIn    дизайн 15×  код 12×      ⚠ bnPop   дизайн 3×  код 0×
  ⚠ bnFade  дизайн  6×  код  2×      ⚠ bnRise  дизайн 3×  код 0×
  ⚠ bnRule  дизайн  2×  код  1×      ⚠ bnBar   дизайн 1×  код 0×
```

Читается так: **разметка и ховеры перенесены почти полностью, а движение — нет.**

- **86 из 89 переходов идут на дефолтной кривой Tailwind.** Дизайн держится на
  `cubic-bezier(0.16,1,0.3,1)` — резкий старт, долгий мягкий выход. Дефолт
  `cubic-bezier(0.4,0,0.2,1)` симметричный и вялый. Это и есть основная причина
  ощущения «микро-анимации не те»: они есть, но с чужой физикой.
- **`cubic-bezier(0.34,1.56,0.64,1)` — кривая с перелётом** (значение 1.56 > 1),
  в дизайне 8 мест: крестик закрытия, поворачивающийся на 90°, столбцы календаря,
  растущие с отскоком. В коде 2 — остальные шесть анимируются линейно-скучно.
- **`duration-200` в 75 местах** там, где в дизайне 240ms. По отдельности 40 мс
  незаметны, но это дефолтная длительность Tailwind, проставленная не глядя — и
  дизайн-система из-за неё «спешит».
- **`bnPop`, `bnRise`, `bnBar` не используются ни разу** — keyframes лежат в
  `global.css`, а вызовов нет. Шесть анимаций появления просто отсутствуют.

## Куда это встроить

В план миграции (`docs/PLAN-next-migration.md`), Этап 1: `tokens.css`
импортируется рядом с `global.css`, `interactions.css` — там же. Оба файла к
фреймворку не привязаны, так что работают и на текущем Astro, и на Next после
переезда. `audit` имеет смысл прогонять в конце каждого этапа вместе со
смоук-чеклистом из 0.3.

Полностью идентичный перенос «как в бандле» невозможен буквально — `style-hover`
не существует вне рантайма артефакта. Но он достижим по результату, потому что
шаблон — это полная машиночитаемая спека, а не картинка.
