## Recovered evidence and fixes

### RENTAL-001 — concurrent rental oversell

Recovered evidence in `apps/cms/src/lib/rental/availability.ts` states that two genuinely concurrent `POST /api/orderItems` requests for a quantity-1 product were reproduced both returning success before the fix. A plain availability read was insufficient because Payload's final write/commit happens after `beforeValidate` returns.

Current fix:

- `lockProductForBooking(req, productId)` obtains `pg_advisory_xact_lock(productId)` on the transaction's own DB session;
- `OrderItems.beforeValidate` calls that lock only on the write path before checking rental/sale availability;
- the transaction-scoped advisory lock releases automatically on commit/rollback;
- public read-only availability endpoints intentionally do not take the lock.

### PERF-004 — indexes on repeated filters

Recovered references identify at least these two hot predicates:

- `orders.status`, used by `activeOrderIds()` in rental/sale availability calculations;
- `products.available`, used by storefront product-list queries.

Both fields now declare `index: true` in their collection configs. This reconstructed file does not infer additional original PERF-004 sub-findings that are not named by the surviving comments.

### SEC-006 — upstream deletion handling

Recovered comments in `apps/cms/src/endpoints/moyskladWebhook.ts` and `apps/cms/src/lib/moysklad/sync.ts` state that DELETE events were previously ignored. The safe behavior is **not** to hard-delete the Payload product because historical order items may still reference it.

Current fix:

- webhook DELETE events are parsed and passed to `handleEntityDeleted()`;
- the matching local product is marked `available: false`;
- per-event sync exceptions are logged;
- genuine webhook processing failures return a non-2xx response so the upstream delivery can retry.

### ACC-001 — date picker accessibility

Recovered comment in `apps/cms/src/components/RentalDatePicker.tsx` records a code-level accessibility finding: the modal lacked dialog semantics, Escape close and focus containment.

Current fix:

- dialog semantics and labelled title;
- programmatic focus when opened;
- Escape closes the dialog;
- Tab/Shift+Tab are trapped inside while open;
- focus returns to the exact trigger that opened the modal.

The original audit comment explicitly notes that this was a code-level pass and that no Lighthouse/screen-reader session was available at audit time. The final manual smoke checklist therefore retains keyboard/browser verification.

### DEPLOY-001 — migration prompt deadlock in detached startup

Recovered comment in `apps/cms/src/scripts/check-migration-drift.ts` records a live reproduction: a dev-mode schema-push marker causes Payload migration tooling to request interactive confirmation, while detached container startup cannot answer it and can remain unhealthy indefinitely.

Current fix:

- migration preflight checks for the `payload_migrations` table;
- if any `batch = -1` marker exists, startup fails loudly before invoking the interactive migration path;
- the error explains that the operator must either resolve/accept drift interactively or discard a disposable test database/volume;
- `PAYLOAD_MIGRATING=true` is set before Payload/config runtime imports so the preflight itself cannot accidentally trigger dev push behavior.

Related deployment hardening preserved in source comments: the hand-authored `rate_limit_hits` table must be protected from Payload dev schema push via the Postgres adapter table filter. That issue is documented next to the preflight because it shares the same dev-push mechanism, but the surviving comments do not identify it as a separate stable audit ID.
